> **代码公开版：** 本仓库不附带模型权重或采集数据。下文涉及的 `.mud`／`.cvimodel` 文件须从你自己的训练任务导出，并按代码配置的路径部署。

# 常见问题

## 运行识别代码提示模型不存在

现象：

```text
model exists: False
```

检查：

- 模型是否复制到 `/root/models/`。
- `.mud` 文件名是否和代码里的 `model_path` 完全一致。
- `.cvimodel` 是否也复制过去。

## 模型能加载，但识别不到目标

可以按顺序检查：

1. 目标是否在画面里足够清楚。
2. 光线是否太暗。
3. `conf_th` 是否太高。
4. 训练数据里是否有类似角度、距离、背景。
5. 标注框是否准确。
6. 模型类型是否和代码匹配。

可以先把阈值降低测试：

```python
objs = detector.detect(img, conf_th=0.35, iou_th=0.45)
```

如果降低后能识别，说明模型有检测结果，只是置信度不够高。

## 误识别很多

处理方法：

- 提高 `conf_th`。
- 增加负样本。
- 增加容易误识别物体的图片，但不要画目标框。
- 检查有没有把错误物体标成目标。

例如训练皮卡丘时，如果模型总把黄色杯子识别成皮卡丘，就多拍黄色杯子作为负样本。

## 远距离识别不好

原因通常是训练集中远距离图片太少。

处理：

- 补拍远距离图片。
- 保证远距离图片里的目标仍然清晰。
- 标注框要准确贴住目标。

如果目标在画面里太小，模型本身也会更难识别。

## 换了目标怎么做

如果你不识别皮卡丘，想识别别的东西：

1. 修改 `拍照.py` 的 `DATASET_NAME`。
2. 重新采集新目标图片。
3. 在 MaixHub 创建新数据集。
4. 设置新的标签名。
5. 重新标注。
6. 重新训练。
7. 下载新模型。
8. 修改 `皮卡丘识别.py` 的 `model_path`。

代码主体不用大改。

## 负样本是不是越多越好

不是。

负样本要和真实场景相关。

好的负样本：

- 真实运行时会出现在画面里的背景。
- 容易被误识别的类似物体。
- 没有目标的桌面、支架、外壳等。

没意义的负样本：

- 和你的场景完全无关的图片。
- 网上随便下载的一堆杂图。
- 质量很差、严重模糊的图片。

## 标注框应该大一点还是小一点

标注框应该贴近目标外轮廓。

不要太大：

- 会把背景也当成目标特征。

不要太小：

- 会漏掉目标的一部分。

目标检测模型学的是“框里的东西是什么”，所以框的质量非常重要。

## MaixCAM 画面不清晰怎么办

先检查：

- 镜头保护膜是否撕掉。
- 目标距离是否太近。
- 光线是否足够。
- 镜头是否有污渍。

如果画面本身不清晰，训练和识别都会受影响。

## 代码缩进需要注意什么

Python 对缩进很敏感。不要在文件开头随便加空格。

正确：

```python
from maix import camera, display, image, nn, app
import os
```

错误：

```python
  from maix import camera, display, image, nn, app
  import os
```

如果报：

```text
IndentationError: unexpected indent
```

通常就是某一行前面多了空格。
