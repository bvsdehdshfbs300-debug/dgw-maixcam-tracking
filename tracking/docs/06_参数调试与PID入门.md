# 参数调试与 PID 入门

让系统“能动”不难，让它“动得稳、追得快、不乱抖”才是调试重点。

## 什么是 PID

PID 是一种控制算法，它根据误差来决定动作大小。

本项目里的误差就是：

```text
目标中心 - 画面中心
```

也就是 MaixCAM 发来的 `dx/dy`。

PID 分三项：

```text
输出 = P项 + I项 + D项
```

## P 项：看现在偏了多少

P 是比例项，对应 GUI 里的 `Kp`。

理解方式：

```text
偏得越远，转得越多
```

如果 Kp 太小：

- 云台追得很慢。
- 远距离目标可能追不上。

如果 Kp 太大：

- 云台容易冲过中心。
- 目标会在中心左右来回摆。

## I 项：看过去一直偏了多少

I 是积分项，对应 GUI 里的 `Ki`。

它适合解决“系统总是差一点点对不准”的情况。

但视觉追踪里 Ki 很容易带来问题：

- 目标已经靠近中心了，积分还没消掉。
- 云台继续动，导致过冲。
- 目标丢失后积分可能残留。

所以本项目默认：

```text
Ki = 0
```

新手建议先不要加 Ki。

## D 项：看误差变化有多快

D 是微分项，对应 GUI 里的 `Kd`。

理解方式：

```text
如果目标正在快速接近中心，就提前收一点力
```

D 项可以减少过冲，让动作更稳。

但 D 项太大也会放大视觉噪声，导致抖动。

## 推荐调参顺序

不要一开始就同时调 Kp、Ki、Kd。推荐：

1. 先让 `Ki = 0`，`Kd = 0`。
2. 只调 `Kp`，让云台能朝目标方向追。
3. 如果太慢，逐渐加大 `Kp`。
4. 如果开始来回冲，稍微降低 `Kp`。
5. 再慢慢增加 `Kd`，让它接近中心时更稳。
6. 最后一般仍然保持 `Ki = 0`。

## 当前代码的默认值

PC GUI 里的默认值：

```text
Kp = 0.12
Ki = 0.0
Kd = 0.006
deadzone = 4
max_steps = 80
min_step = 1
send_interval_ms = 25
smooth_alpha = 0.45
esp_pulse_us = 250
```

这些值偏保守，适合第一次启动。

## 如果追得太慢

可以按顺序尝试：

1. 减小 `esp_pulse_us`，例如从 250 改到 200。
2. 增大 `max_steps`，例如从 80 改到 120。
3. 增大 `Kp`，例如从 0.12 改到 0.16。
4. 增大 `smooth_alpha`，例如从 0.45 改到 0.6。

每次只改一个参数，观察效果。

## 如果不丝滑

常见原因：

- 视觉坐标本身跳动。
- 电机每次收到的步数太零碎。
- Kp 太大导致过冲。
- Kd 太大导致对噪声敏感。
- 机械结构松动或重心不平衡。

可以尝试：

- 适当降低 `Kp`。
- 适当降低 `Kd`。
- 增大 `smooth_alpha` 到 0.5 左右看反应。
- 如果抖动明显，反而降低 `smooth_alpha` 到 0.3 左右。
- 检查云台结构是否晃动。

## 如果靠近中心就不动了

可能是死区太大。

例如 `deadzone = 10`，目标离中心 8 像素时，系统会认为已经够准，不再动作。

可以改成：

```text
deadzone = 3 或 4
```

但死区太小会导致中心附近来回抖。

## 如果方向反了

方向反了不要急着调 PID。先解决方向问题。

现象：

- 目标在右边，云台却让目标更往右跑。
- 目标在上边，云台却让目标更往上跑。

处理顺序：

1. 先确认 GUI 上显示的位置是否和 MaixCAM 屏幕一致。
2. 如果 GUI 显示反了，改 MaixCAM 的 `SEND_INVERT_X/Y`。
3. 如果 GUI 显示对，但电机动作反了，改 GUI 的 X/Y 反向。
4. 如果 X/Y 轴互换，检查接线或固件引脚定义。

## 调参记录模板

建议每次调参做记录，避免越调越乱：

```text
日期：
场景：近距离 / 远距离 / 光线强 / 光线弱
Kp：
Ki：
Kd：
deadzone：
max_steps：
smooth_alpha：
esp_pulse_us：
现象：
下一步：
```

工程调试不是一次调完的。每次只改一个参数，才知道效果来自哪里。
