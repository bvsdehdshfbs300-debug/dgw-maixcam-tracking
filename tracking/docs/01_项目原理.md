# 项目原理

一句话概括：

MaixCAM Pro 找到目标的位置，电脑计算目标偏离中心多少，ESP32-S3 把这个偏差变成电机脉冲，让云台转回中心。

## 为什么要分成三部分

这个项目没有让一块板子做所有事，而是分成三层：

```text
MaixCAM Pro 视觉层
    ↓ UDP 坐标
电脑 PC 控制层
    ↓ 串口命令
ESP32-S3 电机层
    ↓ STEP/DIR 脉冲
二维云台
```

这样做的好处是：

- MaixCAM Pro 擅长跑视觉模型，负责“看见目标”。
- 电脑调参方便，适合做 GUI、显示轨迹、调 PID。
- ESP32-S3 实时输出脉冲更方便，负责“让电机动”。

## MaixCAM Pro 做了什么

MaixCAM 端代码使用：

```python
detector = nn.YOLOv5(model=MODEL_PATH)
```

它会把摄像头画面交给 YOLOv5 模型识别。模型如果发现皮卡丘，会输出类似这样的信息：

- `obj.x`：目标框左上角 x 坐标。
- `obj.y`：目标框左上角 y 坐标。
- `obj.w`：目标框宽度。
- `obj.h`：目标框高度。
- `obj.score`：置信度，也就是模型有多确定这是目标。

程序会算出目标中心：

```python
cx = obj.x + obj.w // 2
cy = obj.y + obj.h // 2
```

再算目标中心和画面中心的差：

```python
dx = cx - img_cx
dy = cy - img_cy
```

这里的 `dx` 和 `dy` 就是视觉误差：

- `dx > 0`：目标在画面中心右边。
- `dx < 0`：目标在画面中心左边。
- `dy > 0`：目标在画面中心下边。
- `dy < 0`：目标在画面中心上边。

## 为什么发 dx/dy，不直接发目标坐标

云台真正关心的不是“目标在第几个像素”，而是“目标离准星差多少”。

所以发送 `dx/dy` 更直接：

```text
TARGET,dx,dy,score
```

例如：

```text
TARGET,38,-12,0.923
```

意思是：

- 找到目标。
- 目标相对画面中心向右偏 38 像素。
- 目标相对画面中心向上偏 12 像素。
- 置信度 0.923。

如果没有识别到目标，MaixCAM 会发送：

```text
LOST
```

## 为什么用 UDP

MaixCAM Pro 和电脑在同一个 WiFi 或手机热点下，MaixCAM 把坐标通过 UDP 发给电脑。

UDP 的特点：

- 简单。
- 延迟低。
- 不需要建立连接。
- 偶尔丢一包也没关系，因为下一帧马上会发新的坐标。

视觉追踪要的是连续刷新，不是每一包都必须送到，所以 UDP 很适合这个场景。

## PC GUI 做了什么

PC GUI 主要做四件事：

1. 监听 UDP，接收 MaixCAM 发来的目标偏差。
2. 在界面上显示目标点相对中心的位置。
3. 用 PID 算法把像素误差变成电机步数。
4. 通过串口发送命令给 ESP32-S3。

PC 发给 ESP32 的典型命令是：

```text
M 12 -5
```

意思是：

- X 轴相对移动 12 步。
- Y 轴相对移动 -5 步。

## ESP32-S3 做了什么

ESP32-S3 不做视觉识别，也不做复杂 GUI，它只负责稳定地产生脉冲：

- STEP 引脚：每来一个脉冲，电机走一个细分步。
- DIR 引脚：决定电机方向。

对于闭环步进电机来说，ESP32 发的是“我要你走多少步”的命令，电机驱动器内部会尽量保证实际转动跟上命令。

## 这就是一个闭环系统

闭环的意思是：系统会不断看结果，再根据结果修正动作。

在本项目里：

1. 摄像头看到目标偏左。
2. GUI 算出需要让云台往左转。
3. ESP32 驱动电机转一点。
4. 摄像头再看目标是否接近中心。
5. 如果还没居中，就继续修正。

所以它不是一次性瞄准，而是不断“看一眼、动一点、再看一眼、再动一点”。
