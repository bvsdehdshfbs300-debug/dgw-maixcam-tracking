> **代码公开版：** 本仓库不附带模型权重或采集数据。下文涉及的 `.mud`／`.cvimodel` 文件须从你自己的训练任务导出，并按代码配置的路径部署。

# 常见问题

这一页按现象排查。先找最像你遇到的问题，再按顺序检查。

## GUI 收不到 MaixCAM 数据

检查：

- MaixCAM Pro 和电脑是否连接到同一个 WiFi 或手机热点。
- MaixCAM 代码里的 `PC_IP` 是否是电脑当前 WLAN 的 IPv4 地址。
- GUI 是否已经点击启动 UDP 监听。
- MaixCAM 和 GUI 的端口是否都是 `8899`。
- Windows 防火墙是否拦截了 Python。

电脑查看 IP：

```powershell
ipconfig
```

## MaixCAM 提示模型不存在

现象：

```text
model exists: False
```

处理：

- 把 `model_280927.mud` 放到 `/root/models/`。
- 把 `model_280927.cvimodel` 放到 `/root/models/`。
- 文件名不要改。
- 路径不要写成 `/root/model/` 或其他目录。

## 串口 COM 打不开

现象：

```text
PermissionError: 拒绝访问
```

原因通常是 COM 口被占用。

关闭这些程序：

- ESP-IDF monitor。
- Arduino 串口监视器。
- 串口调试助手。
- 另一个已经打开的 GUI。

然后重新连接 ESP32。

## GUI 能看到坐标，但电机不动

检查：

- GUI 是否还开着 `dry-run`。
- 是否已经连接 ESP32 串口。
- ESP32 固件是否支持 `M x y` 命令。
- 电机是否独立供电。
- ESP32 GND 是否和电机信号 GND 共地。
- STEP/DIR 是否接到正确引脚。
- 电机是否处于脉冲控制模式。

可以先用手动命令测试：

```text
P 500
M 20 0
M 0 20
```

## 电机方向反了

分两种情况：

### GUI 显示方向就反了

比如目标实际在左下，但 GUI 显示在右上。

处理：

- 修改 MaixCAM 端 `SEND_INVERT_X`。
- 修改 MaixCAM 端 `SEND_INVERT_Y`。

### GUI 显示正确，但电机越追越偏

说明视觉方向是对的，电机方向反了。

处理：

- 在 GUI 中勾选 X 反向或 Y 反向。
- 或交换电机方向线逻辑。
- 或修改 ESP32 固件里的方向输出。

## X 轴和 Y 轴接反了

现象：

- 目标左右移动时，云台上下动。
- 目标上下移动时，云台左右动。

处理：

- 检查 `X_STEP/X_DIR` 和 `Y_STEP/Y_DIR` 是否接反。
- 最推荐从接线上修正。

## 追踪很慢

可以按顺序尝试：

- 减小 `esp_pulse_us`。
- 增大 `max_steps`。
- 增大 `Kp`。
- 增大 `smooth_alpha`。

每次只改一个参数。

## 追踪抖动

可能原因：

- Kp 太大。
- Kd 太大。
- 死区太小。
- 模型识别框跳动。
- 机械结构松。

处理：

- 降低 `Kp`。
- 降低 `Kd`。
- 适当增大 `deadzone`。
- 调整光照，让模型识别更稳定。
- 检查云台结构是否松动。

## 靠近中心后不动了

这是死区在起作用。

如果还没对准就停了，减小：

```text
deadzone
```

如果中心附近一直抖，增大：

```text
deadzone
```

## MaixCAM 能识别，远一点就不行

可能原因：

- 数据集远距离样本太少。
- 训练图里角度和实际场景差异太大。
- 光线变化太大。
- 目标在画面里太小。

改进方法：

- 补拍远距离样本。
- 补拍不同角度样本。
- 补拍不同光照样本。
- 标注时框要贴近目标，不要框太大。

## 中文界面乱码

如果 GUI 或代码注释显示乱码，通常是编码问题。

建议：

- Python 文件保存为 UTF-8。
- 编辑器选择 UTF-8 编码打开。
- Windows 终端显示不影响程序逻辑，但会影响阅读。
